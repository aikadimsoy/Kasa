# KASA Browser Project Status Report

## Executive Summary
KASA Browser is a privacy-focused desktop browser designed to provide ZERO IP/fingerprint leakage for enterprise and security use. Currently in development, the project has built several core security layers but also faces some notable gaps that need addressing.

## Security Shields — BUILT
| Shield | What it does | Status |
|--------|--------------|--------|
| Fingerprint spoof | Spoofs geolocation, canvas/webgl, navigator details to Berlin/DE-DE | Built |
| Proxy/IP hiding | Hides IP via Tor proxy server configuration | Built |
| WebRTC IP-leak prevention | Filters and munges WebRTC candidate lines | Built |
| Sira 0 Level persistence | Stores privacy level in browser memory, survives cross-domain navigation | Built |
| Recent fixes | Prevents new windows/ads from leaking to Chrome; enables DevTools/F12 | Built |

## Gaps / Missing
- Hardcoded de-DE / Berlin inconsistency in navigator spoofing  
  (This directly contradicts the zero-leak goal and is a deanonymization risk)
- AudioContext fingerprint noise + font enumeration defense missing
- Layer #3 Consistency engine not built
- Layer #5 Multi-site research agent bridge + research PANEL not built
- Tabs / real browser chrome functionality missing
- Custom right-click menu missing
- Live verification on real fingerprint/leak sites and proxies not done

## Code Structure
| Module | Responsibility |
|--------|----------------|
| src/browser/browser_window.py | Creates the WebView2 window standalone, injects JS layers |
| src/mcp_server | FastAPI server for VaultTools operations + self-hosted assets |
| src/vault | SQLite DB with Windows DPAPI-encrypted key (no password) |
| src/distill | Distills raw interaction events into durable profile facts nightly or on demand |
| src/export | Exports vault to an encrypted .kasa file with verify |
| src/tray | PyQt5 system tray, vault locked at start |

## Processes & Data Flow
1. run.py: initializes Vault (SQLite) + creates schema -> starts MCP server (FastAPI+uvicorn), DistillScheduler daemon, and KasaTrayApp system tray
2. Browser opens via browser_window.py, injects JS layers on 'loaded'
3. Browsing events posted to localhost:8000/v1/ingest by ingest JS layer
4. Ingest processes browsing events into Vault via VaultTools in MCP server
5. DistillScheduler runs nightly 02:00 or on-demand distillation of raw interaction events into durable profile facts using qwen2.5
6. Export subcommand allows exporting the vault to an encrypted .kasa file

## Multi-site Research Agents — planned design
- Isolated agent contexts run in background, each through proxy+spoof+WebRTC filter
- Per-task identity isolation (anti-linkability)  
- Audit logging of research tasks and results
- Results tagged MEVCUT/EKSIK + chunked for reuse by professor-system format
- Two undecided forks: hybrid fetch vs engine location
